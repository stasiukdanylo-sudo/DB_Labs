# Звіт з лабораторної роботи №6: Керування схемою бази даних та міграції в Prisma ORM

## 1. Оновлення моделі даних (schema.prisma)
До базової схеми, отриманої шляхом інтроспекції (`db pull`), було додано нову модель `review`. Ця модель призначена для зберігання відгуків користувачів на музичні треки.

```prisma
model review {
  id      Int    @id @default(autoincrement())
  comment String
  rating  Int
  trackId Int
  track   track  @relation(fields: [trackId], references: [id])
}
```
Також було оновлено модель track, щоб додати зворотний зв'язок:
```prisma
model track {
  id      Int      @id @default(autoincrement())
  title   String
  // ... інші існуючі поля
  reviews review[] // Зв'язок 1:N
}
```
## 2. Виконання міграції

Для застосування змін до бази даних PostgreSQL була використана команда:

`npx prisma migrate dev --name add_review_table`

Результати виконання команди:

- Prisma порівняла стан schema.prisma з поточною БД.

- Було створено SQL-файл міграції з командою CREATE TABLE "review".

- Структура БД була успішно оновлена.

- Автоматично виконано команду prisma generate для оновлення типів у проєкті.

## 3. Верифікація та заповнення бази даних

Через Prisma Studio було проведено перевірку коректності зв'язків. Оскільки міграція в середовищі розробки може вимагати скидання (reset) даних, було виконано повторне наповнення за ієрархією:
Artist -> Album -> Track -> Review.

## 4. Результати роботи

В результаті виконання роботи було додано функціонал відгуків до існуючої бази даних. Використання міграцій дозволило уникнути ручного написання SQL-запитів ALTER TABLE та забезпечило повну синхронізацію між кодом програми та базою даних.
