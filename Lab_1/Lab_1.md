# Лабораторна робота №1: Збір вимог та розробка ER-діаграми

**Тема:** Проектування концептуальної моделі даних для системи прокату музики

---

## I. Збір вимог

### 1.1 Призначення системи
Організація онлайн-прокату музичних треків та альбомів, керування каталогом виконавців та ведення обліку оренди цифрового контенту.

### 1.2 Завдання користувачів
* **Клієнти:**
    * Перегляд каталогу виконавців, альбомів та треків.
    * Оренда окремих треків на визначений період.
* **Менеджери:**
    * Додавання нових виконавців та альбомів.
    * Оновлення цін на оренду.
    * Керування списком жанрів.

### 1.3 Бізнес-правила
> [!IMPORTANT]
> Ключові правила взаємодії об'єктів у системі:
* **Виконавець** може не мати жодного альбому в системі або мати декілька.
* **Альбом** обов'язково належить одному виконавцю.
* **Трек** обов'язково входить до складу одного альбому та має один основний жанр.
* **Клієнт** може здійснювати багато операцій оренди або не здійснювати жодної.
* **Оренда (Rental)** може містити як один трек, так і цілий список.
* **Пісня (Track)** може бути частиною багатьох замовлень на оренду протягом свого існування.

### 1.4 Дані для збереження
| Категорія | Дані |
| :--- | :--- |
| **Виконавці** | Ідентифікатор, ім'я/назва, країна |
| **Альбоми** | Назва, рік випуску |
| **Треки** | Назва, тривалість, вартість оренди за добу |
| **Клієнти** | Повне ім'я, контактний email |
| **Оренда** | Дата початку, дата завершення, перелік треків |

## II. ER-діаграма

### 2.1 Сутності та атрибути

#### 🎹 Artist
* `artist_id` (**PK**) — унікальний код виконавця.
* `name` — назва або псевдонім.
* `country` — країна походження.

#### 💿 Album
* `album_id` (**PK**) — ідентифікатор альбому.
* `title` — назва альбому.
* `release_year` — рік виходу.
* `artist_id` (**FK**) — посилання на виконавця.

#### 🎵 Track
* `track_id` (**PK**) — ідентифікатор треку.
* `title` — назва композиції.
* `duration` — тривалість у секундах.
* `rental_price` — ціна оренди.
* `album_id` (**FK**) — посилання на альбом.
* `genre_id` (**FK**) — посилання на жанр.

#### 👤 Customer
* `customer_id` (**PK**) — код клієнта.
* `full_name` — ПІБ.
* `email` — електронна адреса.

#### 📅 Rental
* `rental_id` (**PK**) — номер транзакції оренди.
* `start_date` — дата видачі.
* `end_date` — дата повернення доступу.
* `customer_id` (**FK**) — хто орендував.

#### 🔗 Rental_Item (Асоціативна сутність)
* `rental_id` (**FK**) — посилання на транзакцію.
* `track_id` (**FK**) — посилання на трек.

### 2.2 Зв'язки
| Зв'язок | Тип | Опис |
| :--- | :--- | :--- |
| **Artist — Album** | `1:M` | Виконавець випускає альбоми |
| **Album — Track** | `1:M` | Альбом містить перелік треків |
| **Genre — Track** | `1:M` | Жанр класифікує треки |
| **Customer — Rental** | `1:M` | Клієнт оформлює оренду |
| **Rental — Track** | `M:M` | Через `Rental_Item`: оренда складається з багатьох треків |

## Висновок
Під час виконання лабораторної роботи було спроектовано концептуальну **ER-модель** для системи прокату музики. Було визначено основні сутності, їхні атрибути та зв'язки, що враховують бізнес-логіку процесу оренди. Створена модель дозволяє уникнути критичного дублювання даних та є готовою до подальшої фізичної реалізації в середовищі **PostgreSQL**.
